# 00 — 产品合同与不可妥协项

## 1. 产品定义

KnightFrame 是 Windows 优先、Rust 实现的本地桌面编程代理框架。它的竞争力不来自堆叠更多按钮、prompt 或模型调用，而来自四件事：

1. 让主模型以尽可能少的上下文准确理解项目；
2. 让工具返回恰好足够的信息，并能精确修改；
3. 让供应商前缀缓存稳定命中；
4. 让所有可选智能都明确、可关闭、可度量，不暗中花钱。

产品优先级从高到低为：

1. **省钱**；
2. **快速**；
3. **完成质量与模型能力提升**；
4. **最好用的工具**；
5. **最美丽且不臃肿的 UI**。

这些目标并不互相独立：项目速查和精确工具同时降低 token、延迟与错误；稳定缓存同时降低成本和首 token 时间；清晰 UI 使用户知道这些能力是否真正执行。

## 2. 发布成功标准

### 2.1 成本门槛

正式版必须在预先冻结的真实编程任务集上，以相同主模型、相同模型参数、相同初始项目状态、相同任务成功标准，对比同版本 Claude Code：

```text
KnightFrame 成功任务平均实际费用 <= Claude Code 的 80%
```

同时必须满足：

- 任务完成率不低于基线；
- 严重错误率不高于基线；
- 不能用更便宜或更弱的主模型冒充 harness 节省；
- 不能以估算价格冒充供应商真实账单；
- 不能只挑缓存热态、简单任务或失败任务；
- 必须分别报告冷启动、热缓存、短任务、长任务和工具密集任务。

未省到 20% 即视为未通过，不以“接近”“理论上”“某些任务”替代。

### 2.2 质量门槛

默认综合评分继续采用既定权重：

```text
完成度 50% + token 效率 30% + 速度 10% + 灵活度 10%
```

每个 agent 对每个不同任务只运行一次；通过足够宽的任务集减少偶然性，不用同一任务反复刷分。评分器及测试器与 KnightFrame 主程序保持独立。

### 2.3 Windows 门槛

“能在开发机运行”不算完成。所有 `shipped` 功能必须在干净 Windows 虚拟机和实际签名安装包上验证：

- 安装、升级、卸载；
- 无明显终端窗口；
- 长路径、中文路径、空格路径、大小写差异、UNC 路径；
- PowerShell 与进程树取消；
- 睡眠恢复、网络中断、应用崩溃恢复；
- DPI、缩放、多显示器和最小窗口尺寸；
- UI 中英文完整性；
- 不把旧版本缓存或旧项目状态误当作当前状态。

## 3. 六条架构硬约束

### 3.1 主模型唯一负责主任务

只有主模型能：

- 推理并推进用户目标；
- 请求项目、读取、编辑、运行等工具；
- 决定最终回答；
- 在 TaskManager 中提交任务进度。

副模型不能编辑文件、调用项目工具、直接回答用户或悄悄改变主任务。详见 [02-model-roles.md](02-model-roles.md)。

### 3.2 能用本地确定性逻辑，就不用模型

默认采用关键词、索引、规则、长度门槛和结构化压缩。副模型不是“更聪明的默认开关”，而是用户为某一功能单独选择的可选项。

默认状态：

| 能力 | 默认 |
|---|---|
| 需求压缩副模型 | 关闭 |
| Skill 副模型路由 | 关闭 |
| 记忆副模型判断 | 关闭 |
| 记忆存储 | 关闭 |
| Skill 本地关键词匹配 | 开启 |
| SkillOpt | 保留，离线/低频工作，不进入每轮热路径 |
| TaskManager | 开启 |
| Caveman Lite | 开启 |
| 项目速查 | 开启；项目就绪前不进入代理工作区 |

### 3.3 项目速查本地必须全量

“全量”指：

- 所有未忽略文件都进入项目清单；
- 所有受支持语言文件都构建完整符号与关系；
- 配置、测试、资源、文档和未解析文本至少可定位与检索；
- 索引持久化并增量更新；
- 可判定新鲜、更新中或过期，不得把过期图谱伪装成可用。

全量存储不等于向模型倾倒全量内容。模型查询只返回命中的最小精确结果。

### 3.4 工具必须先天简洁，不靠事后截断掩盖噪声

原生 Rust 工具优先返回结构化事实。CLI/MCP 的完整输出留在本地，模型只收到模型投影。压缩顺序固定为：

1. 工具原生结构化结果；
2. 确定性字段投影；
3. 内容类型专用压缩；
4. 明确截断并给出继续位置；
5. 只有用户启用且净节省为正时，才允许副模型参与语义压缩。

任何失败都必须保留状态、错误类型、关键诊断、退出码和完整性标记。

### 3.5 模型边界不出现长哈希和内部账本

模型和普通 UI 只使用短句柄与递增版本，例如 `S7`、`F3/v12`、`R8`。内部为了缓存校验、变更检测或内容寻址而使用的指纹不得进入 prompt、工具结果或普通用户界面。

文件编辑以短版本号、精确位置和旧文本校验为主，不让模型复制长串校验值。

### 3.6 功能必须有存在感，但存在感不能污染 prompt

每项功能必须满足四项合同：

| 项 | 含义 |
|---|---|
| Trigger | 何时触发，默认是否开启 |
| Receipt | 用户当轮和历史中如何看到它确实执行 |
| Metric | 效果、成本、延迟、失败如何度量 |
| Acceptance | Windows 安装包上怎样自动验收 |

回执和指标进入本地事件账本与 UI，不自动进入主模型上下文。模型只获取推进任务所需信息。

## 4. Token 预算原则

每个进入主模型上下文的字节都必须回答一个问题：“它如何提高这次任务的成功率？”

### 4.1 常驻内容

常驻内容只允许：

- 极短核心行为约束；
- 当前稳定工具 schema；
- 当前供应商必须的协议字段；
- 当前会话固定语言与输出风格。

### 4.2 按需内容

以下内容只在命中后追加到尾部：

- 被选中的 Skill 正文；
- 项目速查查询结果；
- 被选中的记忆；
- 动态权限、当前任务状态；
- 工具模型投影。

### 4.3 禁止常驻内容

- 全部 Skill 名单或全文；
- 全项目目录树；
- 全量项目图谱；
- 完整工具日志；
- 内部事件、指标、价格表、功能说明；
- 动态时间、Git 状态、随机 ID；
- 用户未开启的副模型能力说明；
- 为“保险”重复表达的规则。

## 5. UI 产品合同

### 5.1 视觉方向

- 黑、白、中性灰；不得出现偏蓝灰或彩色主调；
- logo 只在品牌位置和空白态使用，避免反复出现；
- 剑、盾等简化符号可用于系统卡片和工具卡片；
- 圆角、细边界、层次阴影与克制辉光；
- 呼吸辉光只用于当前活动、确认焦点和极少数关键状态；
- 无臃肿常驻侧栏，低频设置折叠或进入命令面板；
- 空白态使用缩小后的白色剑徽与输入框衔接，保持视觉平衡。

### 5.2 行为方向

- 正常对话输出与工具卡片分层，诊断日志折叠在下方；
- 计时、token、缓存与费用独立显示，不混入回答；
- 只展示供应商实际提供的 reasoning summary；不得伪造或要求隐藏思维链；
- UI 状态来自事件账本，不从文本日志猜测；
- 所有可见文本来自统一国际化资源，不在 Svelte、Rust 或系统托盘代码中直接写字符串。

## 6. 明确不做或后置

第一阶段不做：

- 群聊与复杂多代理协作；用户后续提供专门参考项目后再设计；
- 默认语义 embedding、“16 维记忆”或无法证明收益的向量卖点；
- 背景遥测、硬件派生 ID、默认上传项目片段；
- 大而全的渠道、定时任务、媒体生成、浏览器生态；
- 为兼容预训练工具习惯而暴露重复的 `ls`、`grep`、`read_file`、shell 包装；
- 复制 Claude Code 反编译 prompt、内部常量或实现；
- 把所有参考项目功能拼在一起。

## 7. 反模式清单

出现任意一项必须阻止合并：

1. UI 写着“已启用”，但没有本轮执行回执；
2. 项目图只是给人看的可视化，模型仍反复列目录和整文件读取；
3. 一行修改导致整文件或大段旧内容进入模型；
4. 工具失败经压缩后看起来像成功；
5. 每轮注入完整 Skill 列表、记忆列表或项目树；
6. 副模型默认调用，或只配置一个全局开关却承担多种隐式职责；
7. 用模型名猜 provider，未知开源模型静默套默认协议；
8. 动态内容插入稳定前缀，破坏供应商缓存；
9. 使用长哈希、绝对内部路径和指标账本占用模型 token；
10. 以不同模型、不同任务或失败任务构造“节省 20%”；
11. 接受 Skill/MCP 字段却完全不执行也不报退化；
12. 组件、locale、通知渠道各维护一套文案；
13. Windows 最后补做；
14. 为极小概率问题在热路径叠加多轮校验、模型评审和冗余 prompt；
15. 参考项目的 benchmark 数字未经本项目复现实验就写进宣传。
