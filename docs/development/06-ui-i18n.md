# 06 — 桌面 UI、视觉系统与国际化

## 1. 体验目标

UI 必须同时做到：

- 黑白、克制、有力量感；
- 正常对话像成熟产品，不像终端日志查看器；
- 工具、计时、token、缓存和费用各有清楚位置；
- 低频功能折叠，不用臃肿侧栏占据空间；
- 每项重要能力有可见回执，但不把屏幕塞满徽章；
- 中英文从第一天共同开发；
- Windows 上静默运行，不弹终端窗口。

## 2. 信息架构

### 2.1 顶栏

固定但紧凑：

- 左侧：完整白色骑士 logo 仅出现一次，后接 `KnightFrame`；
- 中部：当前项目/会话标题和项目速查状态；
- 右侧：新任务、命令面板、设置、窗口控制；
- 不显示旧 `LexSilva`、拼写错误的 `KightFrame` 或重复 logo；
- 品牌文字 `KnightFrame` 可作为允许的品牌常量，其余文案全部资源化。

### 2.2 主工作区

```text
┌──────────────── 顶栏 ────────────────┐
│                                      │
│  会话时间线 / 空白态                 │
│  - 用户消息                          │
│  - 主模型正常输出                    │
│  - 工具卡片与 reasoning summary      │
│                                      │
│  TaskManager 紧凑进度                │
│  输入框 + 附件 + 发送                │
└──────────────────────────────────────┘
```

计量面板不是常驻宽侧栏：桌面宽屏时可作为右侧窄浮层/检查器，普通窗口时折叠为输入框上方一行小票。用户可以固定，但默认不侵占对话宽度。

### 2.3 低频入口

以下内容进入命令面板或模态设置页，不常驻侧栏：

- provider 与模型；
- 主/副模型功能开关；
- Skill、SkillOpt、记忆；
- MCP；
- 权限；
- 项目速查详情；
- 主题、语言和高级诊断。

设置页按搜索和分组定位，所有更改说明是否立即生效、下一 Turn 生效或需要重建项目速查。

## 3. 空白态

空白态使用用户指定的白色剑徽裁剪版本：

- 删除底部倒三角倒影区域；
- 图形底边直接与输入框上边缘衔接，视觉上像剑插在输入框上方；
- 图标尺寸必须克制，不超过空白态可用高度约 22%，不压过输入框；
- 默认只显示一次图形、输入框和一条短提示；
- 不再放第二个完整骑士 logo；
- 窗口变窄时图标进一步缩小，而不是挤压输入框；
- 白色主体，透明背景；禁止旧橙色残留。

图形裁剪、缩放和输入框衔接使用可复现的设计 token 和视觉回归图，不依赖运行时手调绝对像素。

## 4. 视觉系统

### 4.1 色彩

只允许黑、白和中性灰：

```text
canvas       #080808
surface-1    #0F0F0F
surface-2    #151515
surface-3    #1D1D1D
border       #303030
text         #F5F5F5
text-muted   #A1A1A1
text-dim     #707070
inverse      #080808 on #F5F5F5
```

实际值在设计 token 中确定，并通过无偏色测试。状态不能依靠彩色表达：

- 成功：实心白/高亮边界 + 对勾；
- 运行：白色呼吸边界 + 动态符号；
- 失败：双线边界/警告符号 + 文案；
- 阻塞：虚线/盾牌符号 + 文案；
- 取消：低对比删除线/停止符号。

任何状态都必须同时有图标或文本，不能只靠明暗。

### 4.2 圆角与层次

- 主卡片：18–24px 的 Apple 式连续圆角；
- 小控件：10–14px；
- 胶囊只用于短状态和切换，不把所有按钮做成胶囊；
- 边界细、阴影深度低；
- 工具卡片用内层结构和间距区分，不叠加多个粗边框。

### 4.3 辉光

辉光是材质，不是颜色：

- 使用白/中性灰透明光；
- 主按钮 hover/focus、当前运行卡片、输入框聚焦可使用；
- 呼吸周期慢、振幅小；
- 同屏最多 1–2 个呼吸元素；
- 失败、费用、普通文本不使用辉光；
- `prefers-reduced-motion` 时关闭呼吸和位移动画；
- 低性能模式关闭 blur，仅保留边界变化。

### 4.4 图标

- 完整骑士 logo：顶栏与关于页；
- 剑：空白态、执行、edit；
- 盾：权限、安全、阻塞；
- 图谱：项目速查；
- 沙漏/刻线：时间；
- 不在每张卡片重复完整 logo；
- 全部图标提供统一 16/20/24px 光学尺寸与 `aria-label`。

## 5. 对话与输出

### 5.1 主模型输出

主模型的回答按照正常聊天产品显示：

- Markdown、代码、表格、文件链接；
- 流式更新但避免每 token 布局抖动；
- 最终文本与中间工具日志分开；
- Caveman Lite 影响模型输出风格，UI 不再二次截断最终回答；
- 用户可复制原始回答。

### 5.2 Reasoning

- 只显示 provider 明确返回、允许展示的 reasoning summary 或 thinking block；
- 不请求、重建或伪造隐藏思维链；
- reasoning 与最终回答使用不同卡片和标签；
- 默认折叠，流式时显示活动状态；
- token 计量使用 provider usage，不能用可见摘要长度估算全部 reasoning；
- provider 不返回时不显示空卡片。

### 5.3 工具卡片

卡片固定三层：

1. 标题：图标、工具名、当前状态、耗时；
2. 结果：模型也得到的关键事实或适合用户看的结构化视图；
3. 诊断：默认折叠的完整日志/artifact、权限、参数和错误。

不同工具样式一致，只以图标和内容布局区分。禁止把未处理 stdout 直接作为主卡片主体。

### 5.4 Edit 卡片

- 显示文件、修改位置、字符增删和最小 diff；
- 展开可看完整本地 diff；
- 版本冲突时显示“已过期，需要重读”的资源化状态；
- 多文件事务作为一个组展示；
- formatter 额外变化单独标记。

## 6. 独立计量面板

必须独立显示：

- 本轮耗时与会话耗时；
- 总 token；
- fresh input、cache read、cache write、output/reasoning；
- 生成速度；
- 模型请求次数；
- 主模型/副模型分项；
- 实际费用或明确标记的估算；
- 需求压缩、工具投影、项目速查避免量等节省回执。

计量不能遮挡对话或进度条。窄屏采用折叠卡，宽屏采用独立窄列；组件布局使用 CSS grid 的明确 min/max，不用绝对定位叠加。

异常数值防护：

- provider usage 缺失时显示 `unavailable`，不显示 N/A token 参与评分；
- token 突然达到百万级时标记来源和可疑状态；
- 速度必须使用真实 output token/生成阶段秒数；
- cache read 不重复计入 fresh input；
- 费用来源可展开。

## 7. Task、项目与功能回执

### 7.1 TaskManager

- 当前步骤和 `done/total` 独立于工具卡；
- 进度文字永远位于进度条外部，禁止重叠；
- 取消按钮固定可达，但不使用刺眼彩色；
- 阻塞时显示用户可执行动作；
- 完成后收起为一行摘要。

### 7.2 项目速查

首次索引采用专用就绪页：

- 阶段、文件数、语言、覆盖率、失败数、ETA；
- 取消和“文本模式继续”；
- 完成后自动进入工作区；
- 不能只显示没有事实的循环动画。

工作区顶栏用极短 `Ready/Updating/Stale` 状态；点击进入索引检查器。

### 7.3 功能回执

需求压缩、Skill、记忆、cache、fallback 等回执进入计量/功能抽屉：

- 默认只显示发生过的功能；
- 未启用功能不在每轮重复显示；
- skip 原因可在诊断模式查看；
- 不能从设置开关推断“本轮已执行”。

## 8. 国际化架构

### 8.1 单一 catalog

第一阶段支持：

```text
en-US
zh-CN
```

英文为结构基准，两份资源 key 必须完全一致。未来语言包从同一 key 集扩展。

目录：

```text
resources/locales/en-US.json
resources/locales/zh-CN.json
```

Tauri、托盘、通知、安装器可使用同一源文件生成各平台格式，不能另维护第二套字典。

### 8.2 后端合同

Rust 只返回稳定 code/key 与参数：

```json
{
  "key": "error.session.rename_failed",
  "args": { "name": "demo" },
  "cause": "provider_timeout"
}
```

Rust 不返回已经翻译的 UI 句子。provider 原始错误只进入诊断详情，用户消息由 UI catalog 格式化。

### 8.3 前端规则

Svelte 组件：

- 文本节点、placeholder、title、aria-label、toast、空态、按钮全部使用 key；
- 品牌名、文件内容、用户内容、模型内容和标准技术标识不翻译；
- 复数、数字、日期、相对时间和货币使用 locale formatter；
- 参数 placeholder 在所有语言中必须一致；
- 缺失 key 回退英文并计入本地诊断；正式构建缺失 key 直接失败。

### 8.4 Locale 选择

优先级：

1. 用户明确选择；
2. Windows locale；
3. `en-US`。

语言包加载完成后再切换，避免同屏半中文半英文。用户切换同步影响 UI、通知和下一 Turn 的主模型输出语言片段；不重写历史消息。

### 8.5 核心 key 示例

```text
app.brand
composer.placeholder
clarification.large_input.title
clarification.large_input.body
clarification.large_input.enable
clarification.large_input.skip
clarification.large_input.cancel
task.state.running
project.index.stage.parse
tool.state.running
usage.cache_read
error.provider.timeout
```

`clarification.large_input.body` 的中文值必须为用户指定语义：“检测到大量文本信息，要开启需求澄清吗？”。

## 9. 防硬编码门禁

CI 执行：

- 中英文 key parity；
- placeholder parity；
- 未使用 key 报告；
- Svelte 文本节点、属性和 toast 硬编码扫描；
- Rust 用户可见字符串扫描；
- 托盘、通知、安装器资源覆盖；
- 英文模式中的中文泄漏和中文模式中的非技术英文泄漏截图检查；
- 所有错误码与功能 receipt key 都有翻译。

允许清单只能包含：品牌名、标准、模型 ID、文件扩展名、快捷键和测试 fixture。每个允许项需写理由。

## 10. 可访问性与性能

- 键盘完整操作和可见 focus；
- 对比度达到 WCAG AA；
- 状态不只靠颜色；
- 屏幕阅读器能读任务、工具和计量更新，但高频 stream 不反复打断；
- 动画支持 reduced motion；
- 200% DPI、125/150/175% Windows 缩放；
- 最小窗口不重叠，宽屏不无限拉长文本；
- 10,000 行 raw log 使用虚拟列表；
- 流事件批处理，60fps 目标下无明显卡顿；
- 应用窗口启动不伴随终端窗口。

## 11. 视觉验收

必须保存并人工审核以下截图基线：

- 空白态：默认、窄窗口、高 DPI；
- 中文和英文长输入澄清弹窗；
- 普通回答、reasoning summary、工具卡、edit、失败、权限；
- Task 运行、阻塞、完成；
- 项目索引首次构建和 Stale；
- 计量面板宽屏/窄屏；
- 设置页与命令面板；
- reduced motion 与高对比模式。

自动视觉回归检查组件遮挡、文字/进度条重叠、溢出、logo 尺寸和非中性颜色。最终人工验收基于 Windows 打包版。
